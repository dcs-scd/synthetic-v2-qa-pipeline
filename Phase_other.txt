# 3. Migration / patch guide for `run_500k_synthetic.py`

Now the practical part: how to graft `synthetic_v2` into the existing system.

You have two choices.

---

## Option A: run `synthetic_v2` as a parallel runner
Best for lower risk.

### Pros
- minimal disruption
- easier debugging
- compare old/new acceptance rates

### Cons
- duplicate orchestration code for a while

If you want to move fast safely, do this first.

---

## Option B: patch the current runner to use the new routing/prompting/validation
Best for long-term simplification.

### Pros
- one generation pipeline
- easier operations
- less duplicated code

### Cons
- riskier initial integration

## Stage 1
Run `synthetic_v2` as a parallel pilot for 1k–10k examples.

## Stage 2
Patch `run_500k_synthetic.py` to use `synthetic_v2` modules internally.

That gives you evidence before replacing the old logic.

from qa_system_v2bis.synthetic_v2.prompt_builder import build_prompt

# 7. Production adapter integration sketch

Here is the cleanest way to patch the current system with minimal code churn.

---

## 7.1 Add a small bridge module

Create:

```text
qa_system_v2bis/synthetic_v2/production_runtime.py
```

Example:

```python
# qa_system_v2bis/synthetic_v2/production_runtime.py

from qa_system_v2bis.synthetic_v2.adapters import (
    RotatingClientAdapter,
    ExistingEmbeddingIndexAdapter,
    ExistingQuestionSimilarityAdapter,
)
from qa_system_v2bis.synthetic_v2.gate3_dedup import InMemoryDedupIndex

def build_runtime(rotating_backend, embedding_backend, question_sim_backend):
    llm_client = RotatingClientAdapter(rotating_backend)
    embedding_index = ExistingEmbeddingIndexAdapter(embedding_backend)
    dedup_index = InMemoryDedupIndex(
        similarity_backend=ExistingQuestionSimilarityAdapter(question_sim_backend)
    )
    return {
        "llm_client": llm_client,
        "embedding_index": embedding_index,
        "dedup_index": dedup_index,
    }
```

Then your production runner just imports one builder.
